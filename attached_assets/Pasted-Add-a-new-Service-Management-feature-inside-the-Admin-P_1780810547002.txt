Add a new Service Management feature inside the Admin Panel.

Requirements:

1. Create a new Admin Panel section called "Service Management".

2. This section should allow administrators to:

   * Enable any service
   * Disable any service
   * View the current status of each service (Active/Inactive)

3. Supported services should include all current and future dashboard services, such as:

   * Number Search
   * Vehicle Search
   * Email Search
   * Aadhaar Search
   * Any additional services already present in the system

4. UI/Design Requirements:

   * Use the exact same design system already used throughout the Admin Panel.
   * Same card style
   * Same spacing
   * Same typography
   * Same colors
   * Same shadows
   * Same border radius
   * Same responsive behavior
   * Same animation style
   * Same mobile layout structure

5. Do NOT:

   * Redesign the Admin Panel
   * Change existing layouts
   * Modify existing functionality
   * Change navigation structure
   * Affect existing services

6. Functionality:

   * Each service should have an ON/OFF toggle.
   * Changes should be saved instantly or through the existing settings save mechanism.
   * Disabled services should automatically be hidden or blocked from use on the user dashboard.
   * Enabled services should immediately become available again.

7. Real-Time Dashboard Synchronization:

   * The Service Management system must be directly linked to the existing Dashboard Status section that shows whether services are Online or Offline.
   * When an admin disables a service, its dashboard status should automatically update to Offline in real time.
   * When an admin enables a service, its dashboard status should automatically update to Online in real time.
   * No page refresh should be required.
   * Both Admin Panel and Dashboard must always show synchronized service states.
   * The service status displayed on the dashboard should always reflect the actual state configured in Service Management.

8. Backend Requirements:

   * Store service status in a centralized configuration/settings system.
   * Ensure service status persists after server restarts and deployments.
   * Use a single source of truth for service status so both Dashboard Status and Service Management read from the same configuration.
   * Add proper validation and logging for all enable/disable actions.

9. Security:

   * Only Admin users can access and modify Service Management settings.
   * Non-admin users must never see this section.

10. Future-Proofing:

* Any new service added in the future should automatically appear in the Service Management section.
* The same service should automatically appear in the Dashboard Status section.
* No major code changes should be required when adding new services.

Goal: Add a Service Management section to the Admin Panel that allows administrators to enable or disable services while keeping the Dashboard Status indicators synchronized in real time and preserving the existing UI, UX, design language, structure, and behavior completely unchanged.
